# Security Policy

## Supported Versions

ForgeGuard is early-stage. Only the latest release receives security updates.

| Version | Supported |
| ------- | --------- |
| 0.x     | ✅        |

## Reporting a Vulnerability

If you discover a security vulnerability in ForgeGuard itself (not in the
vulnerable demo fixtures, which are intentionally vulnerable), please:

1. **Do NOT** open a public GitHub issue.
2. Email the maintainer directly (see GitHub profile for contact).
3. Include a description of the vulnerability and steps to reproduce.
4. If possible, include a suggested fix.

We aim to respond within 5 business days.

## Scope

The following are considered **in scope** for security reports:

- The ForgeGuard policy engine (`security/`)
- The GitHub Actions workflows (misconfigurations, credential leaks)
- The Dockerfile (base image vulnerabilities)
- The infrastructure code (`infra/`)

The following are **out of scope**:

- The deliberately vulnerable demo app endpoints (they exist to be vulnerable)
- Third-party scanner output that ForgeGuard merely processes
- Known CVEs in pinned base images (these are tracked via Grype)

## Security Assumptions

ForgeGuard assumes:

1. Scanner output files are generated by trusted CI runners
2. The policy YAML files are reviewed through pull requests
3. The `GITHUB_TOKEN` has least-privilege permissions
4. Container images are signed with cosign keyless signing

## Disclosure Policy

We follow responsible disclosure: 90-day embargo for critical vulnerabilities
before public disclosure.
